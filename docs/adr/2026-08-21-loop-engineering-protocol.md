# ADR: 학습 루프 엔지니어링 프로토콜

- 날짜: 2026-08-21
- 상태: 승인
- 맥락: AI가 과제를 대신 완성해 학습자의 코드 이해가 사라지는 것을 막으면서, 작은 검증 단위로
  Rust 학습을 진행한다.

## 결정

사용자가 **"다음 루프 시작"**이라고 말하면 아래 사이클을 한 번만 수행한다.

1. `git status`, `git log`, `TODO.md`로 현재 과제 하나를 고른다.
2. 목표, 입력, 검증 명령, 최대 3회 수정, 중단 조건과 제외 범위를 먼저 선언한다.
3. 기본 maker는 사용자다. AI는 테스트 또는 인터페이스를 함께 설계하고 사용자가 직접 구현할
   지점에서 멈춘다.
4. 사용자가 구현한 뒤 AI는 별도 검토 패스로 정확성, Rust 관용성, 불필요한 `clone`, panic 경로를
   검사한다.
5. 최종 트리에서 `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`와
   과제의 실제 CLI 실행을 검증한다.
6. 합격한 코드만 커밋하고 완료된 TODO는 제거한다. 상태 문서는 만들지 않는다.

## 역할 예외

사용자가 전체 구현을 명시적으로 위임하면 AI가 maker가 될 수 있다. 이 경우에도 구현 패스와 리뷰
패스를 분리하고, 사용자가 diff에서 소유권·오류 경로·자료구조 선택을 이해할 수 있게 설명한다.

## 외부 부작용 경계

`git push`, `cargo publish`, 외부 서비스/API 호출, credential 접근, 저장소 밖 변경과 파괴적 데이터
변경은 루프 밖에 두며 매회 사용자 승인을 받는다.

## 중단 조건

- 수정과 재검증은 최대 3회다.
- 외부 의존성이나 요구사항의 중대한 갈림길이 발견되면 구현하지 않고 보고한다.
- 루프 하나가 끝나면 연속 실행하지 않고 사용자의 다음 트리거를 기다린다.
